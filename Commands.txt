1. PREREQUISITES AND ENVIRONMENT CHECK
================================================================================

Before running anything, verify your environment.

Open PowerShell or Command Prompt (cmd) and run these commands ONE AT A TIME.

--------------------------------------------------------------------------------
1.1 Check Java version
--------------------------------------------------------------------------------

    java -version

Expected output:
    openjdk version "17.0.x"  or  openjdk version "25.0.x"
    OpenJDK Runtime Environment ...
    OpenJDK 64-Bit Server VM ...

--------------------------------------------------------------------------------
1.2 Check Java compiler version
--------------------------------------------------------------------------------

    javac -version

Expected output:
    javac 17.0.x   or   javac 25.0.x

--------------------------------------------------------------------------------
1.3 Check Maven version
--------------------------------------------------------------------------------

    mvn -version

Expected output:
    Apache Maven 3.8.x  or  3.9.x
    Maven home: ...
    Java version: 17.0.x or 25.0.x
    Java home: ...

The Java version shown by Maven MUST match the version shown by javac.

--------------------------------------------------------------------------------
1.4 Verify JAVA_HOME (Windows)
--------------------------------------------------------------------------------

In PowerShell:

    echo $env:JAVA_HOME

In Command Prompt:

    echo %JAVA_HOME%

Expected output (example):
    C:\Program Files\Eclipse Adoptium\jdk-17.x.x-hotspot
or
    C:\dev\tools\jdk-25_windows-x64_bin\jdk-25.0.2

If JAVA_HOME is empty, see Section 8 (Troubleshooting).

8. TROUBLESHOOTING
================================================================================

Problem: "No compiler is provided in this environment"
Cause:   Maven is using a JRE, not a JDK.
Fix:
    1. Verify JAVA_HOME points to a JDK folder (contains bin\javac.exe)
    2. In cmd:  echo %JAVA_HOME%
    3. Ensure %JAVA_HOME%\bin is FIRST in PATH
    4. Restart all terminals
    5. If still broken, edit C:\dev\tools\apache-maven-3.9.12\bin\mvn.cmd
       and add as line 1:
       set JAVA_HOME=C:\dev\tools\jdk-25_windows-x64_bin\jdk-25.0.2

--------------------------------------------------------------------------------

Problem: "Unknown lifecycle phase .mainClass=com.klh.dsa.Demo"
Cause:   PowerShell stripped the -D prefix.
Fix:     Always quote the -D argument:
             mvn exec:java "-Dexec.mainClass=com.klh.dsa.Demo"
         Or use cmd instead of PowerShell.

--------------------------------------------------------------------------------

Problem: "Port 8080 already in use"
Cause:   Another app or previous server still running.
Fix:
    1. Close any previous WebServer terminal
    2. Or find and kill the process:
       netstat -ano | findstr :8080
       taskkill /PID <pid> /F
    3. Or change the port in WebServer.java

--------------------------------------------------------------------------------

Problem: "mvn clean compile" fails with "cannot find symbol"
Cause:   Missing file or wrong method signature.
Fix:
    1. Verify all files exist: dir /s src\main\java
    2. Check the error message for the missing class
    3. Ensure the class file exists and package declaration matches folder

--------------------------------------------------------------------------------

Problem: Web UI shows blank page
Cause:   Static files not found.
Fix:
    1. Verify src/main/resources/web/ contains index.html
    2. Verify WebServer.java serves from classpath /web/
    3. Rebuild: mvn clean compile
    4. Restart the server

--------------------------------------------------------------------------------

Problem: "BUILD FAILURE" on first run
Cause:   Missing Maven dependencies (no internet, corporate proxy).
Fix:
    1. Check internet connection
    2. Try again: mvn clean compile -U
    3. If behind proxy, configure settings.xml in C:\Users\<user>\.m2\
